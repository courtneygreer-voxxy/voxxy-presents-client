================================================================================
CRITICAL IMPLEMENTATION DETAILS
================================================================================

1. HTML/TEXT CONVERSION
   Backend stores HTML: <p>[eventName]</p>
   Frontend edits plaintext: [eventName]
   Conversion on load: backendToFrontend() strips HTML, converts {{old}} → [new]
   Conversion on save: frontendToBackend() adds HTML, keeps [bracket] format

2. VARIABLE SYSTEM
   Current format: [bracket] used everywhere
   Legacy format: {{mustache}} auto-converted on load for backwards compatibility
   Variables stored in database: [bracket] format expected
   Frontend validation: Checks for unknown variables and unclosed brackets

3. TIMEZONE HANDLING
   All emails send at 8:00 AM in user's timezone
   Converted to UTC for backend storage
   Preview date calculated with timezone awareness
   Enforced by getEightAmLocalAsUTC() utility

4. INVITATION EMAIL (Virtual)
   Special handling for "Event Announcement (Invitations Sent)"
   Created dynamically with ID -1 (not backed by backend)
   Sourced from eventInvitationsApi delivery stats
   Cannot be edited, only previewed
   Shows invitation delivery statistics

5. PREVIEW WITHOUT REGISTRATIONS
   If event has no vendor applications:
   - API returns "No registration found" error
   - Frontend shows template with [variables] unresolved
   - User cannot test variable resolution without test data
   - Workaround: Create test vendor first

================================================================================
WORKFLOW OVERVIEW
================================================================================

COMPLETE EMAIL LIFECYCLE:

1. Template Selection
   Event → Command Center → Emails tab → EmailAutomationTab loads

2. Email Generation
   User clicks "Generate Scheduled Emails" → Backend creates 10-40 emails

3. Email Customization
   User clicks "Edit" → EmailEditorPage opens → User edits content
   Load: HTML → plain text, Save: plain text → HTML

4. Email Preview
   User clicks "Preview" → EventEmailPreviewModal
   With registrations: Shows resolved variables
   Without registrations: Shows template with [variables] unresolved

5. Email Sending - Automated
   Background job checks scheduled_for time → Filters recipients → Sends via SendGrid

6. Email Sending - Manual
   User clicks "Send Now" → Immediate send via SendGrid

7. Delivery Tracking
   SendGrid webhooks report: sent, delivered, bounced, dropped, unsubscribed
   Backend updates EmailDelivery records
   Frontend displays delivery counts and statuses

8. Retry Failed
   User clicks "Retry Failed" → Retries soft bounces only (temporary failures)

9. Save as Template
   User clicks "Save as Template" → Event's emails saved as reusable template

================================================================================
AREAS FOR IMPROVEMENT
================================================================================

1. HTML Editing
   - No WYSIWYG editor available
   - Plain text only (no bold, italic, lists)
   - Links must use variables ([paymentLink], [eventLink])
   - HTML manually added via <p>, <br> only

2. Preview Testing
   - Cannot preview variables without registrations
   - Requires creating test vendor to test variable resolution
   - Category-specific content needs vendors in that category

3. Recipient Filtering
   - No UI for managing filter_criteria after creation
   - Cannot adjust recipient targeting after email scheduled
   - Applied at generation time, locked in

4. Error Handling
   - Some API errors show generic messages
   - No detailed drill-down into failure reasons
   - Cannot see per-recipient failure details

5. Soft Bounce Retry Limitation
   - Can only retry soft bounces (temporary failures)
   - Hard bounces (invalid emails) permanently skipped
   - User may think retry failed if mostly hard bounces

6. Edit After Send Limitation
   - Cannot edit email after status = 'sent'
   - If error discovered post-send, must create new email
   - No way to update trigger for already-sent emails

================================================================================
POTENTIAL PILOT TEST ISSUES
================================================================================

1. Preview Without Test Data
   Issue: Preview shows [variables] unresolved if no registrations
   Impact: User cannot verify variable resolution before sending
   Workaround: Create test vendor first

2. Delivery Stats Delay
   Issue: SendGrid webhooks may take time to report delivery
   Impact: User may see "0 delivered" immediately after send
   Workaround: Wait a few minutes and refresh

3. HTML Formatting Limitations
   Issue: No WYSIWYG editor, plain text only
   Impact: Cannot create formatted emails with bold, italic, lists
   Workaround: Use plain text or variable links for formatting

4. Soft Bounce Retry Only
   Issue: Retry only works for soft bounces
   Impact: Hard bounces permanently fail
   Workaround: Clean email lists to prevent hard bounces

5. Virtual Invitation Email
   Issue: Cannot edit invitation email after creation
   Impact: If content wrong, must resend via new scheduled email
   Workaround: Preview before inviting vendors

6. Category-Specific Content
   Issue: Limited support for dynamic category variables
   Impact: May show template fallback if vendors missing in category
   Workaround: Create test vendors in all categories

RECOMMENDATIONS
================================================================================

For Pilot Testing:

1. Create test vendors early
   - Enables email preview with resolved variables
   - Allows testing variable interpolation
   - Prevents "No registration found" errors

2. Use preview modal extensively
   - Always preview before final send
   - Check resolved variable values
   - Verify formatting and layout

3. Monitor delivery stats
   - Wait 5-10 minutes after send for full delivery stats
   - SendGrid webhooks take time to report
   - Don't assume failure if initial counts are 0

4. Save successful email sequences
   - Use "Save as Template" for successful campaigns
   - Enables reuse for future events
   - Reduces recreation effort

5. Test with test environment first
   - Verify HTML formatting works as expected
   - Test variable resolution with dummy data
   - Validate SendGrid integration before production

CONCLUSION
================================================================================

The Voxxy Presents frontend email system is a comprehensive, production-ready
implementation for managing automated vendor communications. The architecture
is clean and modular with good separation of concerns.

Primary Strength:
  Full email lifecycle management from creation through delivery tracking

Overall Assessment:
  Well-implemented system suitable for pilot testing with awareness of the
  documented limitations and workarounds.
